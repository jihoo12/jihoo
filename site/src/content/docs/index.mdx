import { Card, CardGrid } from '@astrojs/starlight/components';

```jihoo title="hello.jh"
fn greet(name: str) -> str {
    return "Hello, " + name + "!"
}

fn main() {
    print(greet("jihoo"))
}
```

```jihoo title="args.jh — a native program, calling C"
#![native]
import libc

fn main(argc: i32, argv: **u8) -> i64 {
    libc.printf("%s got %d arguments\n", argv[0], argc - 1)
    return 0
}
```

```jihoo title="tiny.jh — no libc, no GC: a 3 KB static binary"
#![freestanding]

fn _start() -> i64 {
    syscall(1, 1, "hi\n", 3)   // write(1, "hi\n", 3) on x86_64 Linux
    return 0                   // exit(0)
}
```

<CardGrid>
  <Card title="Three profiles, one IR" icon="seti:pipeline">
    Hosted programs run on a VM with a garbage collector. `#![native]` programs
    have no GC, are compiled by LLVM and link with libc; `#![freestanding]`
    ones have no libc either. All share one typed IR, and the test suite checks
    that they agree.
  </Card>
  <Card title="Compile-time everything" icon="rocket">
    `const`, `comptime` and array lengths run ordinary functions on the VM while
    compiling, even for freestanding programs, and bake the results in.
  </Card>
  <Card title="Macros are just functions" icon="puzzle">
    A macro is a function that runs at compile time and returns code: an
    expression, statements, or whole functions and types.
  </Card>
  <Card title="Generics and modules" icon="seti:folder">
    `comptime T: type` parameters, generic structs like `Vec(T)`, and modules with
    `import` and `pub`, including a small standard library.
  </Card>
  <Card title="Down to the metal" icon="setting">
    Raw pointers, arrays, inline asm and `syscall` for compiled code, C functions
    through `extern fn` for native code, and an
    arena allocator and `Vec(T)` written in jihoo itself.
  </Card>
  <Card title="Built with Nix" icon="seti:nix">
    `nix run github:jihoo12/jihoo` gives you the whole toolchain: the VM, the LLVM
    backend, the linkers and the standard library.
  </Card>
</CardGrid>
